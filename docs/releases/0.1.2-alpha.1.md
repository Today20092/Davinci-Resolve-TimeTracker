# 0.1.2-alpha.1 — source preview

This alpha releases compatible reliability fixes since 0.1.1. It is experimental: **Resolve playback can still be undercounted**, and the on-demand dashboard exceeds resource targets. It is not a complete billing-accuracy or performance qualification.

## Fixes and completed work

- Keep status and Pause/Resume responsive while a Resolve SDK read blocks by isolating reads in one owned worker process.
- Discard late observations and uncertain gaps instead of filling them with guessed billable time. Use each Session's persisted Heartbeat/start for stale totals and pause recovery; invalidate reads across Pause/Resume changes.
- Reuse the Resolve connection and reader, recover dead readers, and clean up the Windows reader after an abrupt tracker-parent exit.
- Improve process-tree, CPU, memory and SDK/query accounting in diagnostic benchmarks. Add a timed, isolated dashboard workload.
- Strengthen concurrent-reader, heartbeat-rate, activity-failure and lifecycle coverage. Verify real Windows installer stages and shortcut rollback within a disposable profile-path boundary.
- Document branch/release procedures and native UIManager feasibility results. The native probe remains an opt-in experiment; ordinary installation retains the existing dashboard/runtime.

Explicit launch, no login watcher and on-demand reporting were already present in 0.1.1. This release preserves them. No database schema migration or automatic updater is introduced.

## Validation and known limits

- Automated baseline: 155 Python tests and 34 subtests, Ruff checks, frontend lint/typecheck, 29 frontend tests and production build passed. Windows and Ubuntu CI passed for the integrated baseline; release-PR/tag checks must also pass before publication.
- The real isolated Windows install/reinstall/rollback check passed in 218.51 seconds. Profile discovery was redirected; this does not establish historical managed-install upgrades or clean-machine support.
- Live Windows 11 / Resolve Studio 21.1.1.10: duplicate launch reused the runtime, controls worked while SDK reads were pending, rendering produced a Session, reporting survived Resolve exit, and final detach left zero observed application processes.
- **Playback remains incomplete:** SDK getters, including cached-handle reads, waited for playback to stop. Stale/error status and missed playback time remain in [#52](https://github.com/Today20092/Davinci-Resolve-TimeTracker/issues/52). Do not treat the preview's totals as verified invoices.
- **Resource targets remain unmet with the dashboard:** a combined 352.721-second workload averaged 1.236% of one CPU core and peaked at 428.11 MB aggregate memory. Concurrent development activity and sampling limits apply; this is not a controlled headless comparison.
- Long-render billing, representative editing/recovery dogfooding and actual managed-profile upgrades remain in #52. Native UIManager launch and Stop can also stall during playback; [#57](https://github.com/Today20092/Davinci-Resolve-TimeTracker/issues/57) remains research.
- Fresh Mac installation is [#54](https://github.com/Today20092/Davinci-Resolve-TimeTracker/issues/54), native Mac/X11 checks are [#58](https://github.com/Today20092/Davinci-Resolve-TimeTracker/issues/58), Free compatibility is [#13](https://github.com/Today20092/Davinci-Resolve-TimeTracker/issues/13), and packaging remains deferred in [#20](https://github.com/Today20092/Davinci-Resolve-TimeTracker/issues/20). None is closed by this release.

See the [acceptance evidence](../research/ticket-52-acceptance.md) and [roadmap](../roadmap.md) for remaining work. The existing frontend bundle-size warning and pre-existing exploratory Python type-check diagnostics are not represented as passing type gates.

## Install or update

This release provides GitHub source archives, not a standalone Windows installer or PyPI package. For the exact tagged source:

```sh
git clone --branch v0.1.2-alpha.1 --depth 1 https://github.com/Today20092/Davinci-Resolve-TimeTracker.git
cd Davinci-Resolve-TimeTracker
```

Follow [the source setup and prerequisites](../development.md#set-up). Close Resolve and the dashboard before updating an existing installation, and back up `tracker.sqlite3`. The [bootstrap installer route](../usage.md#bootstrap-current-main) follows current `main`, which may advance beyond this tag. The [README downloads](../../README.md#install) point to this published alpha. Source updates preserve history/settings; older applications are not guaranteed to read newer databases. For this release the schema is unchanged.

Public version/tag: `v0.1.2-alpha.1`. Python package and CLI version: `0.1.2a1`, the same alpha release in Python notation. The private frontend package version is not the application release identity.
