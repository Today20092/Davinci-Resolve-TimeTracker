# Background tracking owns cadence

The Python background tracking module will take Tracking Observations on one five-second cadence and persist Heartbeats no more often than every ten seconds. Dashboard, tray, and event consumers read published state without triggering Tracking Observations; this prevents duplicated Resolve calls and SQLite writes while accepting up to roughly ten seconds of lost recovery precision after an abrupt crash.

A Tracked Launch will start DaVinci Resolve and the Python tracking runtime together; no watcher or tracker process remains resident between Resolve sessions. The dashboard window is created only when requested and destroyed when closed, and every tracker process exits after Resolve exits. This trades automatic coverage of Resolve sessions started through other shortcuts for zero tracker resource use between editing sessions and ensures presentation is not required for tracking correctness.

Only one tracking runtime may own a user's database. Repeated Tracked Launches reuse that runtime, and dashboards connect to it rather than starting another. A dashboard opened without Resolve uses a temporary read-only runtime that exits with the dashboard. If Resolve terminates unexpectedly, the active Session ends at its last persisted Heartbeat; the runtime does not watch for a later Resolve restart.

If a user-opened dashboard remains after Resolve exits, the runtime stops tracking and continues only read-only reporting until the dashboard closes. Once both Resolve and the dashboard are closed, no tracker, Electron, Node, package-manager, HTTP, watcher, or launcher process remains. Automated tests enforce deterministic work and lifecycle counts; a repeatable local benchmark records hardware-dependent CPU, memory, disk, process, and startup measurements without making them flaky CI gates.

Windows activity remains native and is read on each five-second Tracking Observation. macOS and X11 activity adapters sample at most every fifteen seconds only while Resolve runs, publish cached immutable activity state, and never spawn child processes from the five-second tracking path. Missing tools, permissions, malformed output, timeouts, and unsupported Wayland sessions make activity unavailable and pause billable transitions rather than assuming Active Work. Additional PyObjC or custom X11 bindings are deferred until platform measurements justify them.
